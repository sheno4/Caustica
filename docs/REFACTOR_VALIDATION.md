## Slang session close detaches ownership before cleanup (2026-09-09)

Reviewed the Java Slang boundary and session/runtime lock ordering at f73287fa. The regression uses an expired arena segment: Java 25's downcall contract rejects an address argument whose scope is not alive before calling native code, so no invalid pointer is sent to the destructor. On the original implementation the test failed with callback count zero instead of one (tmp/aesthetic-slang-close-before.log, terminal exit1, one failing test). This is controlled failure-path evidence, not a claim that an ordinary production handle expired.

Retained sessions still remain logically closed without native destruction. The runtime callback remains outside the session lock because it acquires the runtime monitor. A second concurrent close can now observe logical closure and return while the first caller completes native cleanup; only the first caller owns destruction and notification.
