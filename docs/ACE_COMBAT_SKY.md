# ACE COMBAT 8 天空适配

`rewrite` 分支上的实验 Fabric 版本 `0.1.0-ac8-sky.3`。它读取 AC8 原始体积云纹理、云体布局、天空参数及场景灯光，再由 Caustica 绘制。原 Cloudly 着色器源码没有恢复，兼容解释保存在独立的 `rendererAdapter` 中。

## 使用

Minecraft 26.2、Fabric Loader 0.19.3 或更高版本、Fabric API，使用 Vulkan 后端。原模组的硬件要求仍适用。

私有资源包放在实例的 `config/caustica-cloudly` 内。在 `config/caustica.toml` 中配置：

```toml
["caustica:minecraft".sky.cloudly]
enabled = true
source-pack = 'D:/Minecraft/config/caustica-cloudly/source-pack-hangar001/manifest.json'
samples = 512.0
max-distance-km = 200.0
```

设置界面使用简体中文，**皇牌空战云层（实验性）** 提供开关、资源路径、采样预算和距离。修改路径后重新进入世界。资源在后台上传；日志记录加载、校验和上传结果。云层仅用于主世界。公开 JAR 不包含游戏资源。

`.3` 的源包需包含单独的 `nativeDefaults` 和 `sceneParameters`，并采用随本版提供的适配声明。不能只替换 JAR 而继续使用缺少这些数据的旧源包。

## 原始数据与解释

本地安装：Steam app `2288340`、build `25201480`，**ACE COMBAT 8: WINGS OF THEVE**。

| 内容 | 恢复结果 |
| --- | --- |
| 天空预设 | `CSP_Hangar001_Daytime01` |
| 云体预设 | `CVC_Hangar001_Daytime01`，4 个分组、31 个云体 |
| 原场景 | `Hangar001_Lit_Daytime02`，实际引用上述两个预设 |
| 体积纹理 | 9 个关联的 `VT_`，512 × 512 × 64、PF_DXT1 / BC1 |
| 原始 mip | 共 90 层、86,283,000 字节，逐份记录尺寸、长度和 SHA-256 |
| 场景太阳旋转 | Pitch −25°、Yaw 18°；取灯光前向的反方向并转换坐标 |
| 原生太阳默认值 | 日面角度 0.535700023°、强度因子 100000、RGB (1,1,1) |
| 云层散射 | 原生默认 4 阶；本预设序列化的衰减 0.5 覆盖原生默认 0.78 |
| 天空灯颜色 | 原场景 sRGB 字节 (200,233,255) |

14 个相关原生默认字段通过静态读取构造函数、属性偏移和常量恢复，带独立证据记录。这不是全部原生默认值。序列化参数优先，缺失的已恢复字段才使用原生默认值；源参数、原生默认值、场景数据、适配假设保持分离。重复静态数组保留为有序数组。

日面角度解释为完整直径、强度因子解释为 lux、RGB 解释为线性 BT.709，均是显式适配约定。Unreal DirectionalLight 使用 lux 的[官方说明](https://dev.epicgames.com/documentation/unreal-engine/using-physical-lighting-units-in-unreal-engine)不能单独证明 Cloudly 内部强度因子的完整传递链。

## `.3` 的渲染变化

- **云层亮度：** 使用同一个场景太阳方向、源强度和颜色；加入 4 阶有限散射近似，并使用原场景天空灯颜色补光。默认环境亮度和有限阶公式仍是适配选择。
- **云层清晰度：** 在 DLSS 重建后，以输出分辨率合成，再参与曝光测光。主射线使用稳定像素中心；地形遮挡使用独立分辨率、带原采样偏移的追踪深度，避免将云层送入没有对应云层深度、运动矢量的重建流程。
- **采样：** 沿源云体包围盒求交、合并区间，按世界体素尺寸与光学厚度缩小步长。预算默认 512，范围 64–1024。根据屏幕足迹选择原 mip，最多使用适配声明中的 LOD 1。
- **细节：** 保留原始粗云体纹理，在边缘加入由源参数驱动的 Perlin/Worley 细节近似。使用 B、C 和薄云位移的世界单元尺寸、频率、权重、重映射、幂和对比度；最多 4 个 octave，位移缩放明确为适配参数。未恢复的 Alto 细节关闭。
- **太阳：** 源预设启用时绘制解析圆形日面，天空 LUT、保留太阳光和云层共享场景方向、强度、颜色及角半径。圆形日面辐亮度按 `E / (π sin²α)` 归一化。

所有原 BC1 通道和 mip 解码后上传为不可变 3D 纹理。云体依源纹理编号、层密度、位置、尺寸、旋转和 UV 放置。源 Z 向上按 `(X,Z,-Y)` 转换，源零高度对齐 Minecraft 海平面。

当前红通道密度、完整尺寸、绝对变换、Z 轴欧拉旋转、恒等密度映射及最大值合并是兼容解释。原 DensityOperation 0 枚举为 Add，但原着色器的具体合成公式没有恢复。支持范围之外的源操作、旋转、剪切和拉伸拒绝导入。

## 边界

细节生成器是根据已恢复参数实现的近似。原噪声种子、扭曲、模糊/锐化核、SDF 生成、垂直压缩和附加表面淡出规则没有恢复，不能声称与原 Cloudly 一致。散射阶数如何对应原渲染循环也没有恢复，本适配将其解释为包含单次散射的总阶数。

云层仍是主视角效果，没有地面云影、次级反射光线中的体积云、Lumen、原始动画、降雨及吸收掩模，也未支持全部预设切换。六点自遮挡覆盖有限距离。空区跳步不是保守 SDF 追踪；采样预算耗尽的区段仍保留背景。

大气和显示变换仍使用 Caustica 的模型。原场景后处理参数作为源数据保留，未将其曝光偏置、胶片曲线及锐化数值直接套入不同的光度校准。

**未启动游戏、未执行图像识别测试；实际画面、性能及与 AC8 的视觉一致性尚未验证。** 新细节和较高采样预算会增加渲染成本。

## 导出、版本与验证

[离线导出工具](../tools/ace_combat_sky/exporter/README.md)使用固定版本 CUE4Parse、托管解压器和本地属性映射，不运行原游戏或游戏 DLL。访问密钥、原生映射和原始资源保存在 Git 仓库外。

转换工具分别接受 `--renderer-adapter`、`--native-defaults`、`--scene-parameters`。后两项需要独立的来源和证据对象，不能用估计值冒充恢复数据。[适配模板](../tools/ace_combat_sky/exporter/caustica-adapter.example.json)只含实现选择。[来源及构建记录](ACE_COMBAT_SKY_PREFLIGHT.json)不含密钥或原始资源。

用户 fork 的独立分支为 `ace-combat-sky`，基线标签 `ace-combat-sky-base-2026-10-02` 对应上游提交 `0cc9d0af4f4118cd26b830084a14f2bafc0d904d`。既有分支和旧版标签保留。

前版完成 34 项相关数值检查；`.2` 完成中文设置及路径保存/读取/清空/重置检查。`.3` 新增 4 项有针对性的检查，覆盖重建后合成顺序、测光输入、太阳圆盘能量与源默认覆盖规则、散射/细节参数。实际私有源包通过新的数值模型检查，确认 31 个云体、9 个纹理关联、场景太阳及细节世界尺寸。未重复运行已通过且未受本次变更影响的测试。

本地 Java、反射 ABI、Slang 和 SPIR-V 编译通过。Windows CI 只构建 Fabric 包，固定 Java 25、Slang 2026.14.1 及原项目 SDK。最终 JAR、源码提交、版本标签和 SHA-256 在打包完成后记入来源记录。
