# AC8 原始天空管线移植

目标是使用安装版本中 Cloudly 的原始算法、纹理、参数换算和时序重建。`.7` 已将原版着色器帧图连接到 Fabric 的重建后通道；游戏内外观尚未验收，不能仅凭 GPU 执行完成宣称效果已还原。

## 当前交付与历史记录

`.19` 新增以方块为单位的云层高度偏移，默认 0、范围 −16000～16000；所有场景共享该实例设置。云采样坐标、追踪包围范围、阴影及 AO 的高度同时平移，大气和实际相机坐标不动。编辑停下 250 毫秒后应用，复用已有纹理分配并重新生成云历史、两级阴影及 AO。此功能完成编译和打包后，实际游戏内效果仍需运行确认。

`.18` 将 MC 相机本帧雾数据的 `renderDistanceStart/End` 作为独立的地形淡出边界，97、109 和 4821 使用相同的柱形距离。大气归一化仍为 300000 米，真实第一命中深度与世界 RR guides 不变，云距离不由地形视距替换。移除 97 下地平线强制切换 LUT 的覆盖，并让 3928 的独立背景积分使用与 3930 相同的空气延拓；原表面 AP 循环、原采样算法及步数保留。地形范围变化会重置云层历史，日志记录实际捕获范围。该范围不是异步发布完成的逐区块覆盖证明，改版后的视觉结果尚未验收。

`.17` 的同一 Fabric JAR 内包含机库、任务 3 和任务 11 三个真实源场景，中文菜单选择后在世界内后台准备并自动切换；准备期间继续使用旧场景。`.16` 用户日志确认任务 11 因重复登记程序 3925 而在读取阶段失败；`.17` 保留原条目、移除执行合同完全相同的冗余条目，并在导出与 JAR 打包前检查编号唯一性。任务 11 为 79 个唯一程序，未修改编译代码与阶段算法。`.13` 用户运行日志确认任务 3 在读取入口被旧近似模式声明检查拒绝，`.14` 修复读取后完成任务 3 准备与激活，但第一帧被 AO 非零清除声明拒绝。`.15` 移除六张 AO 工作/历史纹理的多余清除声明，由原始程序完成全部 32/64/64 块预生成后再采样；没有跳过 AO 计算。用户正常运行 `.15` 的日志确认任务 3 在 3840×2160 提交原始云帧、首次完成 160 个 AO 分块，并能在机库与任务 3 之间双向切换。该证据不包含画面与 AC8 的对照验收。精度/追踪预算选项及宿主预算字段已移除；主追踪保留原始 128 次循环、含空区 256 次循环的上限。开关、场景和距离由独立的 `CloudlyOptions` 定义。公开 Actions 产物没有私有资源，不能替代本地整合包。

任务 11 来自 `Map07/Mission011/Mission011_Common_Lit_Cloudly01` 直接引用的 `CSP_ms11_251209` 和 `CVC_ms11_250814`，包含 123 个云体、16 张体积纹理。独立恢复其 D/BSDF3 的 10 次原始 283 归一化与 3925 三轴标量模糊，并通过原始 3175 连续厚度检测、距离场生成、2326 标量二维切片和 2327 mip 构建真实雨柱。该源场景原本启用雨云，在 Minecraft 晴天仍保留。雨柱用 R16F 保存原始编码数值而不声称恢复原 BC4 分配；任务 11 新增部分未经过游戏/GPU 执行或视觉验收。

任务 3 使用其地图直接引用的 `CSP_Mission003_kanno260131`、`CVC_Mission003_kanno250202`、44 个云体和 14 张原始体积纹理。独立重建该场景的构造默认值、序列化覆盖、噪声、距离场、双通道高层云及动态采样参数；原场景太阳强度为 120000，颜色来自任务 3 灯光。

任务 3 的环境遮蔽连接原始 65 积分程序的三个层级、吸附中心及 32/64/64 帧分块更新。首次绘制前用同一原始程序生成完整历史，后续周期完成才发布对应中心与纹理。宿主采用原始浮点分支配 R32 浮点容器，保留积分结果而不额外量化；原生产分配使用 67/68 的 BC4 压缩分支，不能将这两种存储描述为相同。任务 3 启用的高层云位移通过原始 65 与 62 共有的完整距离场算法执行，宿主 62 根据原建模位 7 选择该分支；机库的该位仍关闭。

`.9` 的统一地平线切线填色会造成恒定灰带，已撤销。`.11` 使用每个方向对应的原版大气 LUT；向虚拟地面延伸的背景按有限大气路径积分，路径随方向及相机高度变化。云影和多重散射在地平线连续接入；实际地形、云相机与云深度不因背景延拓而改动。这是 Minecraft 无几何背景边界的宿主适配。

以下为历次恢复与运行证据，涉及旧版状态的描述不作为当前安装说明。

`.9` 将云层距离设置连接到实际的云/卷云追踪上限；各阶段的距离归一化独立使用原生 renderer 的 300000 米，避免 250000/300000 混用导致错误的云与地形前后关系。改变距离设置或帧不连续时不复用旧云历史。环境零深度在深度降采样入口直接返回远距哨兵，避免无限远反投影的非数值结果。无实际地形且射线落入虚拟地球的背景使用同一原版大气 LUT 的天空侧切线辐亮度延拓，修复 Minecraft 未加载区域的暗色带；处理发生在云合成前，不覆盖云。实际几何深度、云密度与光照保持原版路径。低于源海平面的相机仅在大气切线平方根处限制非负值，不移动云相机。此次按用户要求只编译打包，未追加测试或图像识别。

`.8` 修正了原版粗追踪与主云追踪的相机手性不一致：源程序 58 原本仍以 `cross(ViewForward, ViewRight)` 构造竖直方向，在宿主的右/前/上坐标中得到反向竖直轴；主云追踪 62 已使用真实宿主逆投影。粗追踪返回的错误空区距离会让细追踪跳过实际存在的云。58、4820 和 4821 现在也使用统一的宿主相机桥接，保留源追踪、光照、纹理、密度和质量参数。按用户要求只编译打包，没有追加测试或图像识别。

`CloudlyOriginalPass` 使用源包中的 `source.nativePipelineManifest` 选择原版管线。源体积纹理、蓝噪声和月球等纹理完成上传后，先生成原版大气及密度，再执行原版阴影、深度处理、瓦片分类、云追踪、时序重建和大气合成。宿主场景颜色在世界重建后进入原版合成，最终从线性 BT.709 转回 ACEScg；世界 RR 的 guides 保持对应原来的世界渲染。

2026-10-22，独立的 Java/Vulkan 执行器在 RTX 5090 上完成了源纹理上传、三个原版大气生成阶段、完整 141 阶段密度生成，以及 640×384 的连续 20 帧原版帧图。Vulkan 校验没有报错。没有图像读取、图像识别或游戏进程。此后修正了有限远投影深度符号，并为两个大气程序加入与主云管线一致的宿主相机桥接；按用户要求不再追加测试，直接打包。这些证据不包含 Minecraft 内的视觉验收或目标分辨率性能测量。

所有私有 Slang 程序必须使用 `-spirv-unified-descriptor-heap-stride`。引擎以统一 slot 存放混合描述符，按单独 buffer 大小索引会访问错误地址；真实设备上 image descriptor 为 32 字节、buffer descriptor 为 16 字节。私有库导出器核对 SPIR-V 的统一 stride，公开加载器要求 `unifiedResourceHeapStride=true`。

原版程序及游戏资源仅供用户本机私有部署；`.11` 包含于本地整合 JAR，不进入公开 Fabric JAR、GitHub 或 Actions 产物。当前速度输入选择原版相机和距离重投影分支；动态物体速度尚未单独导入，遮挡边缘的时序表现仍有待游戏内确认。

## 已有实现

- 从本地全局着色器缓存与 IoStore 着色器组取得原始 DXIL，并从调试元数据恢复 HLSL。原始代码、编译结果与游戏资源保存在私有目录中。
- `tools/ace_combat_sky/port_shader.py` 保留原始计算函数，把 root constant-buffer 的寄存器字节偏移映射为 GPU 地址，把原始常量结构与资源访问映射到 Caustica 的描述符堆。
- 72 个私有程序已编译为 Vulkan SPIR-V，通过 `spirv-val --target-env vulkan1.4`。程序覆盖密度合成、跳跃洪泛距离场、距离场编码、云追踪、天空环境光、大气透视、阴影、时序重建，并包括原版深度降采样、重投影、瓦片分类、棋盘恢复及阴影末级降采样。
- 通用程序核对 24,568 个字段偏移；噪声程序核对另外 421 个字段偏移。编译结果中没有传统 descriptor-set / binding 装饰。
- `CloudlyShaderLibrary` 加载私有程序库，校验资源哈希，提供原始字段布局、不可变参数上传和共享 GPU 所有权。通道选择放在各次 dispatch 的独立 push payload 中，避免连续记录后全部读到最后一次通道值。
- 异步计算执行器在每个 command-buffer 开始后绑定平台描述符堆，让后台原始程序生成资源时遵循与帧内 dispatch 相同的 ABI。
- `CloudlyVolumeBake` 按明确给出的原版计划执行二维/三维纹理生成、各级 mip、复制与跳跃洪泛 dispatch。单层 sampled view 保证 mip 程序读取指定的上一层；同格式复制保存锐化所需的原始量化数据。输出与临时资源分别持有，GPU 完成后才转交输出。
- `CloudlyBakePlan` 读取私有配方，冻结经过哈希校验的完整常量、绑定和 push 输入，拒绝未解决执行依赖的配方。原版光学深度→多重散射→远处天空光三阶段配方通过真实 Java 加载、绑定及 push 编码检查。
- 相机桥接以宿主逆投影恢复光线，并映射到原版 X/负宿主 Z/宿主 Y 坐标。云追踪、大气合成、时序重建的桥接变体已编译。`CloudlyFrameUniforms` 提供厘米矩阵、当前与上一帧视图、深度与抖动；已向 33 个真实原版 View 布局写入并核对字段类型与尺寸。
- `CloudlyFrameArena` 仅在帧的最后 GPU 所有权释放后复用常量缓冲区。`CloudlyFramePrograms` 共享 shader object，用帧独立的不可变数据记录原版 dispatch 和阶段间依赖，避免逐帧覆写仍在读取的数据与反复分配内存。
- 原版瓦片追踪支持 GPU 间接调度：参数缓冲随帧保留，分类后的 storage 写入在 `DRAW_INDIRECT` 读取前建立依赖。设备初始化明确查询并启用 `textureCompressionBC`，支持原始 BC6H 月球 cubemap；仅物理设备支持压缩格式不足以证明逻辑设备已启用该能力。
- `CloudlySourceBuffer` 区分结构化组件缓冲与原版天空采样点的 float4 texel 缓冲。`CloudlyColorBridge` 在原版线性 BT.709 合成器与宿主 ACEScg 之间转换，保留 HDR 与预曝光值；桥接程序已编译并通过 SPIR-V 验证。
- `CloudlyStatisticsBuffer` 提供原版 uint texel min/max 输出与完成后的映射读回；生成任务记录 GPU→宿主依赖，读回时 invalidate 非一致缓存。`CloudlyUniformExpressions` 执行私有字段配方，保留 float32 运算、延迟分支与整数掩码。
- `CloudlyOriginalBakeResources` 将私有生成配方连接到已上传源纹理、不可变组件缓冲、统计缓冲和完成地址。当前配方包含 46 张纹理、141 个有序阶段。统计读取实际生成通道，CPU float4 的未用通道保留原版回调的 −1；GPU 完成后才发布输出。
- `CloudlyFrameRecipe` 冻结私有帧参数，按原版顺序发布已更新参数的别名，检查各字段的类型与偏移。阶段只读取自己消费的 uniform；不读取未选择阶段或分支的依赖。4 项数值测试与实际大气合成、时序重建程序的 13,584 字节参数、View、完整 heap 表和 push 编码检查通过。未完成的帧计划不能标记为可执行。
- `CloudlyFrameSchedule` 读取原始阶段和资源配方，校验有序依赖、实际图像尺寸、typed heap 表、每次原生 subpass 覆盖及间接调度缓冲范围。真实私有帧图的 28 个阶段、23 个计算绑定表、394 个绑定项、50 张图像和 6 个缓冲通过 CPU 数值检查。云自身的原始历史独立维护，97/109 在世界 RR 后的独立工作图像完成源合成，避免把云颜色送入仍描述地面的 RR guide。此框架尚未在 GPU 运行。
- 72 个真实程序的私有资源哈希、完整 typed heap 表及无隐式 bound uniform 已检查，覆盖 64,333,944 字节 SPIR-V 与 35 个 View 布局。原始帧纹理的真实 Java 加载核对 19 个 mip、109 个上传区域及 4,980,880 字节，其中 cubemap 占 108 个区域。相机数值测试 3 项、配方冻结与复制测试 3 项通过；原有程序库 ABI 测试 6 项已通过。没有执行 GPU 画面测试。

## 原生参数恢复

已从原生构造函数的完整调用链与序列化覆盖恢复源场景 SkyParams。太阳 RGB 强度直接为 100000，原生太阳倍率为 1；云层密度除以 CloudDensityExtintionBalance，散射系数同时乘以该平衡值。大气模板已恢复太阳、大气、相函数与环境光参数，仍需补齐宿主帧输入和部分运行时字段。

原版基础云与中层云距离场范围为 Z=0..25000 m，512×512×64，距离场 texel 为 390.625 m。云层起始高度 600 m 是单独的渲染参数，不能当作生成体积的起始高度。近卷云距离场为 1024×1024×2，texel 为 195.3125 m；远卷云原生 texel 为 200 m。渲染时由原始 100 m 软夹层裁切。这些尺寸与原版按米计算的细节位移配合使用，不能用纹理采样倍率代替。

## 接入要求

不能将源体积贴图的红通道直接当作最终云密度。原始流程合成组件密度，生成并编码距离场，再以世界单位进行云边缘位移、密度换算、跳步和散射。云的光照读取原始天空光照 LUT；不能以固定环境光替代。

宿主提供 Minecraft 的相机、深度与场景颜色，并进行源坐标、厘米与米、线性 BT.709 与 ACEScg 的明确转换。源程序需要的参数由源序列化字段、实际原生默认值和原生填充函数共同决定。未证实的字段应保持未解决状态，不能用猜测值生成完整参数块。

资源生成在后台进行，完成 GPU 工作后才发布。逐帧执行的相机与时序数据必须使用帧独立的不可变缓冲区；尺寸变化时重建并重置对应时序历史。

原生帧顺序中，大气合成程序 97 先于时序重建 406；97 没有云颜色输入，不能作为最终云合成器。最终云颜色还经过原版 ReconstructCloud 与 GenerateBlendRes。深度降采样与重投影 ID 是时序程序的真实依赖；这些步骤和阴影、粗追踪的连接仍在补齐，不能以空白纹理代替。

## 验证边界

目前的证据是原始资源读取、编译、SPIR-V 与字段偏移校验，以及 Java 资源与参数 ABI 测试。尚未证明新管线在游戏内的画面或帧率。没有进行图像识别测试，没有启动游戏进行截图测试。

`0.1.0-ac8-sky.4` 的运行时仍使用近似云通道。它复用同一点、同层的细节噪声，缓存不可变纹理尺寸，并剔除不与当前视线相交的组件；阴影保留完整组件集合。1024 步、距离、分辨率和光照参数不因此降低。GPU timestamp 仅在完成后非阻塞读取，用日志报告云 dispatch 的耗时，没有读取图像。

这些运行时优化已经编译，Java/Slang 组件布局再生成一致；实际 GPU 帧率收益尚未测量。原版完整管线还没有切换进运行时，不能将 `.4` 当作 AC8 效果已还原的版本。用户配置保持原值。

Fabric `.4` 的 Action `37184320884` 已通过，产物 SHA-256 为 `31ef37f38dfdf55723e6a209ca29c510f363f319432f30e43be2a1da133040b9`，Git 标签 `v0.1.0-ac8-sky.4` 指向运行时修复提交 `d398cffa`。在确认实例已退出后替换旧包，保留旧包与配置备份；没有为验证启动游戏。

用户正常运行 `.4` 后，日志记录云 dispatch 平均 142.83–276.44 ms，最大 456.48 ms，输出 2562×1486。`.5` 将云颜色接入重建前的 scene-effect 链，使用该链自身的相机抖动。用户随后正常运行 `.5` 的日志记录输出 854×495，日间多个区间平均约 11.19–40.82 ms，最高区间峰值 60.48 ms。观察条件和相机在变化，不能据此报告同场景 FPS 提升率；算法开销仍很高。

`.5` 的天空、保留太阳光源和云照明均使用当前 Minecraft 太阳角度与用户设置的正午倾角。源场景太阳提供原版能量、颜色及圆盘尺寸，源快照方向不再覆盖世界时间。云外观仍由近似通道产生，原版完整帧图尚未接入；这次修复不构成 AC8 外观验收。

## sky.6 回归修复与剩余工作

`.5` 在 RR 前只改场景颜色，没有更改深度、运动、材质、法线等 guide。该颜色与 guide 不再对应同一场景，属于集成错误。`.6` 在 trace 分辨率分别输出介质散射和透射率，保留世界重建的输入，在重建完成后、曝光统计之前组合 `scene * transmittance + scattering`。全分辨率阶段只读取介质结果，不执行全分辨率云 ray march。当前介质结果仅做深度边界过滤，尚未连接原版时序历史，不应声称它有 AC8 的时序重建质量。RR 引导输入要求见 [NVIDIA 集成说明](https://github.com/NVIDIA-RTX/Streamline/blob/main/docs/ProgrammingGuideDLSS_RR.md)。

固定云环境光原来为 `250 * 3.718518 = 929.6295 cd/m²`，与昼夜无关，且每阶散射继续累加。`.6` 删除这个常量，改为每帧积分太阳/月亮天空 LUT 得到平均入射辐亮度；云读取该结果以及实际大气透射和行星遮挡。月光读取源 `MoonFractionOfSunIntensity`，保留 Minecraft 的方向、时间和月相；源快照关闭月亮的场景选择不冻结宿主昼夜。源包须包含经过来源校验的该字段及其原生默认值。可见太阳圆盘使用中文设置中的显示角尺寸；物理光源半径仍独立，用于阴影和遮挡。

本地 Minecraft rendering 的 150 项测试及两个着色器组编译已通过，包括太阳运动、月相能量、显示尺寸与物理半径独立、原版向量构造、帧配方和原始 cubemap 上传布局测试。补齐本地 Slang DLL 后，其运行时检查也已通过；NGX 测试改为验证构造条件及路径处理，避免依赖已移除的私有字段。该证据不包含 GPU 运行、画面识别或视觉验收。

Fabric Action 现在执行根 `build`，包括所有 Java 模块测试和 Slang tooling 检查；失败时保留测试报告，正式 jar 只在成功后上传。native cache key 包含已初始化的 NRD 子模块实际提交，避免只有 submodule 指针变化时复用旧 NRD DLL。

原版帧图的关键尺度已恢复：深度断层 mask 为 `ceil(T/8)`，重投影与云追踪为 `ceil(T/2)`，瓦片分类为 `ceil(T/16)`，原版 406 时序重建输出完整 T，109/112 对场景颜色进行最终云合成。蓝噪声及两个天球 cubemap 的 19 个原始 mip 已私有保存，包括六面层序、压缩块、全部 hash 和上传区域。未使用空白纹理替代真实依赖。两级阴影的原生滚动缓存状态、其余大气生产步骤与实际帧调度仍需连接；当前生产云渲染依然是明确标记的近似通道。
